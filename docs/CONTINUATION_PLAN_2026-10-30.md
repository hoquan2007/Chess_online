## Delivery discipline

- Keep changes small on `codex/chess-platform-foundation` or another development branch; for each slice use discover → plan → code → test → review → fix → record evidence. Read bundled Next 16.4 docs before changing Next APIs.
- For every completed slice record code diff, actual commands/exit codes, live versus mocked scope, security review, open defects and rollback instructions in `TEST_RESULTS.md` plus `AUTONOMOUS_PROGRESS.md`; keep `BACKLOG.md`, `ACTIVE_TASK.md`, `NEXT_ACTION.md` and `FEATURE_MATRIX.md` synchronized.
- **Gate rule:** local 52/52 unit, 40/40 browser and Webpack build PASS are the current baseline; they are prerequisites, not replacements, for hosted acceptance. Never promote a feature on the strength of skipped tests, mock data, structural SQL alone or a READY Vercel build.
- Do not merge into `main`, push unrelated changes, change production access controls, or deploy production without explicit owner approval.
