## Findings fixed in this slice

`e2e/rookline.spec.ts` previously assumed the bundled application never had Supabase keys. A locally configured build correctly displayed **Sign in to play**, **Sign in to see player rankings**, and returned `401` for anonymous same-origin profile update, while tests demanded unavailable-service copy and `503`. Three failures therefore came from the test's environment assumption, not established application behavior. Assertions now require the precise expected copy for either supported public-service state, consistently verify the profile state using the leaderboard's public configuration, and accept only the valid `401`/`503` API contract with its exact error body. They continue requiring `403` on cross-origin mutation. Focused Chromium **3/3 PASS** followed by full Chromium **101 PASS / 3 SKIP**.
